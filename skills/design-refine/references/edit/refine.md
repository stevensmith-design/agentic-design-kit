# Refine verbs — applying an approved plan

**Precondition: an unlocked run and an approved plan.** A locked run never opens this file; if it
has, stop and report the plan instead. `apply.md` comes first; this file adds what each verb must
watch while it edits. The rules themselves stay in `ui-design-principles/references/rules.md`.

## polish

Fix in the plan's triage order and finish each tier before the next: a visual tweak never goes in
while a broken task or missing state from the plan is still open. Fix drift at its source — the
token or the shared component — not per instance.

## bolder

Edit only the surface in scope; neighbours keep their own intensity. Structure first (scale
contrast, focal point, rhythm), and re-run the skeleton test after the structural edits, before
anything decorative. No new colour, effect or typeface unless the plan named it and it was
approved.

## quieter

Remove intensity sources in the ranked order from the plan and stop when the surface reads as
calm. Re-check the identity sentence from the plan after each round: a quieter page that no longer
looks like this product has gone too far — undo the last round.

## distill

Every removal from the plan either moves its function (disclosure, another screen) or is
recorded as removed. Nothing a user needed disappears without a line in the report.

## clarify

Change words, not structure. One name per thing across every screen touched; update every place a
renamed label appears, including tests and analytics events that match on text.

## colorize, typeset, layout

Through tokens only. **colorize:** a hue the system does not declare is a stop. **typeset:** a
typeface change is a stop; sizes come from the declared scale. **layout:** spacing comes from the
scale; after the edit, run the squint test again on the render.

## animate, delight

Every motion gets its reduced-motion form in the same edit. Durations and easing come from the
system's motion tokens (or `rules.md` → *Motion* when there are none). **delight:** only the
moments the plan named; nothing added on the critical path.

## onboard

Empty states get their content in the same edit as their layout: what appears here, why it is
empty, how to start. Optional steps stay skippable.

## overdrive

Build only the direction the person picked. The fallback ships in the same edit and is checked on
its own: effect off, reduced motion, a throttled device.

## Variants

Asked for several versions of one thing: say what is on screen first (the identity to keep); the
default variant keeps the identity, and a departure changes it only where the person asked. **Each
variant moves one axis** — hierarchy, layout topology, type, colour strategy, density or how the
content is broken up — so a pick tells you which axis mattered. Five at most.
